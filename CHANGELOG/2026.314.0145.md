# 2026.314.0145 — refactor(schema): derive the cua word sets from vocabulary tables

## Summary

Replace the three inline `|` word unions in `candy/plugin-cua/schema/cua.cue` with the §10.1 S3
vocabulary-table idiom, so each closed set of words has ONE home and the enum an author meets is
`or()` of that table's keys:

```
_delivery  _permissionMode  _method          (+ _deliveryWord / _permissionModeWord / _methodWord)
```

That is the 30 `union` rows `design/dpat-baseline.tsv` records for
`plugin-cua/candy/plugin-cua/schema/cua.cue`. **They are THREE disjunctions, not 30:** `delivery`
and `permission_mode` are each written on one line (one row each), and the method catalog is
written one alternative per line, which is the other 28 rows — its 29th word, `call`, closes the
disjunction and carries no `|`, so it never had a row. A union's row count is a property of its
formatting, so the row number is the only honest way to compare repos and it is not a count of
disjunctions.
